# Журнал устройства и компактные карточки

Журнал хранится в SQLite отдельно для каждого Tuya-аккаунта и локального транспорта. Доступ требует ключа API и проверки принадлежности устройства выбранному аккаунту. Endpoint `GET /api/v1/activity/devices/{id}?provider=sharing|developer|local&limit=50&before=...` возвращает события от новых к старым и курсор `next_before`. Для локального устройства используется ID записи. Хранятся последние 2000 событий на устройство в каждом источнике; история сохраняется после перезапуска и недоступна другому аккаунту.

У датчиков движения журнал открыт в основном разделе, у остальных устройств — свёрнут. Можно отфильтровать движение или команды и загрузить более ранние события. Пока журнал открыт, интерфейс читает его раз в три секунды; скрытая страница и закрытый журнал не опрашиваются. Это чтение базы, без запросов статуса каждого устройства в Tuya.

Sharing подписывается на отчёты устройств после загрузки инвентаря и продолжает принимать их при закрытой карточке. Метаданные преобразования DP загружаются только при открытии устройства или его первом фактическом отчёте. В журнал попадают новые отчёты, включая повторное срабатывание движения с тем же значением, если время события изменилось. Повторная доставка того же отчёта и запоздалые отчёты не создают новые события. Для отчётов без времени устройства используется время приёма. Основная дата отчёта — время устройства, когда оно известно; время приёма показано отдельно.

Сохранённые снимки явно обозначены и записываются только при первом чтении или изменении значения. Старый HTTP-снимок не заменяет реальный отчёт в журнале. Developer записывает доступные снимки и команды; локальный транспорт — полученные нормализованные показания и команды, включая чтение фоновым сборщиком дисплеев. Новые фоновые LAN-опросы ради журнала не запускаются. История до подключения журнала не восстанавливается и не выдаётся за реальные события.

Запрос команды и его результат являются отдельными событиями. ACK означает принятие команды, а не подтверждённое физическое состояние. Отказ и неизвестный результат различаются; автоматических повторов нет. Локальные ключи, токены и приватные вложенные поля не сохраняются в событиях; большие составные значения обозначаются без полного содержимого. Алиасы и ручные сопоставления пока не входят в журнал команд и показаний.

Батарея показывается вверху справа в открытой карточке и под состоянием сети в списке. Инвентарь возвращает только доступное значение батареи, не загружая отдельно статус и функции каждого устройства. Единица и масштаб берутся из известных метаданных; `battery_percentage` обозначает проценты, а `va_battery` и legacy `battery` без единицы показывают исходное число. Неизвестный заряд не угадывается. Параметры `va_temperature`, `va_humidity`, `va_battery` переведены, измерения снабжены иконками и компактным расположением.

Питание и другие логические настройки редактируются одним переключателем. Его выбранное состояние является черновиком до общей кнопки «Применить»; пока команда не подтверждена новым показанием, фактическое значение остаётся подписано отдельно. Устаревший известный статус отмечается, неизвестный статус не считается выключенным.

Суточный ритм, случайное расписание, свет для пробуждения и перед сном редактируются во всплывающих мастерах: повторение → точки расписания → проверка. Одновременно редактируется одна точка. «Готово» возвращает черновик в карточку, «Отмена» ничего не меняет; отправка выполняется общей кнопкой «Применить». Нераспознанный формат сохраняется, а создание нового расписания требует явного действия. Исходные данные доступны в свёрнутом техническом разделе мастера.
