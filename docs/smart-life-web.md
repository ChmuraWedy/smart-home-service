# Проверка Smart Life Web

Дата проверки: 2026-10-07. Проверен реальный вход в публичный [Smart Life Web](https://eu.device.tuya.ai/login) через QR и подтверждение владельцем в мобильном приложении. Вход в браузере Tuya не авторизует автоматически Sharing SDK нашего сервиса: это разные клиенты и сеансы.

Tuya [описывает публичную веб-версию](https://www.tuya.com/vas/commodity/OEM_WEB) как бесплатную для пользователей Smart Life / Tuya Smart; отдельные расширенные функции могут потребовать подписку в будущем. Условия OEM Web — отдельный продукт.

## Что подтверждено после входа

В проверенном аккаунте список и топология показали 44 устройства, 19 online и 25 offline на момент просмотра. Топология отобразила два шлюза и суммарно 21 дочернее устройство. Эти числа описывают один снимок аккаунта, а не пределы веб-версии.

| Данные | Результат проверки |
|---|---|
| Названия, Tuya device ID, PID, категория, online/offline | Видны в списке |
| Дом и вложенные помещения | Видны в дереве и расположении устройств |
| Родительский шлюз | Видны связи шлюз → дочерние устройства в Smart Toolkit → Device Network Topology |
| MAC и тип связи | Видны в Device Info проверенной Wi-Fi лампы |
| IP | В карточке показан замаскированный адрес внешнего подключения; это не подтверждение локального LAN IP |
| `local_key` / `localKey` | В просмотренных экранах не показан; наличие в ответах API **не проверено** |
| Zigbee `cid` / `node_id` | В просмотренных экранах не показан; наличие в ответах API **не проверено** |
| LAN protocol version 3.x | Тип связи Wi-Fi/Bluetooth в карточке не является версией LAN-протокола |
| Экспорт | Кнопка Export доступна; получение и содержимое файла в этой проверке не подтверждены |

Важно: `nodeId` в коде визуализации топологии строится из `device.id`. Это ID узла графа, а не доказательство наличия Zigbee `cid` / `node_id`. Его нельзя автоматически переносить в поле TinyTuya `cid`.

## Наблюдавшиеся запросы и публичный код клиента

В инвентаре загруженных ресурсов наблюдались следующие маршруты. Они описывают внутренний веб-клиент и не являются обещанием стабильного публичного API:

- `/open-api/v1.0/m/sdf/space/trees` и `/open-api/v1.0/m/sdf/space/home/tree` — дерево помещений.
- `/open-api/v1.0/m/sdf/device/pag/source-query` — запрос списка устройств.
- `/open-api/v1.0/m/sdf/device/capability/list` — каталог фильтров по типам связи.
- `/open-api/v1.0/m/sdf/device/index/<device_id>?project_id=<project_id>` — подробные сведения.

Публичный [код раздела устройств](https://static1.tuyaeu.com/static/smart2c-app-device/0.0.0-156/static/js/main.2738d81d.js) содержит запрос подробных сведений и операции экспорта `/open-api/v2.0/m/sdf/device/export` и `/open-api/v2.0/m/sdf/device/export/task`. Проверенный bundle не содержит `local_key` / `localKey`. Отсутствие строки в интерфейсном коде **не доказывает**, что сервер не возвращает такое поле.

Публичный [код Smart Toolkit](https://static1.tuyaeu.com/static/smart2c-app-toolbox/0.0.0-109/static/js/main.2ab6b559.js) показывает построение графа из ID устройств, дочерних списков и сведений о шлюзах. Наличие структуры топологии полезно для будущего импорта родителей.

## Что осталось проверить

Тела авторизованных JSON-ответов не были прочитаны. Встроенный браузер предоставил адреса ресурсов, но не тела сетевых ответов; прямое открытие наблюдавшегося API-адреса было заблокировано браузером. Попытка чтения окна обычного Chrome остановлена автоматической проверкой из-за метаданных других приватных вкладок. Это ограничение текущей проверки, а не отказ Tuya выдавать ключи.

После открытия второго браузерного сеанса первая вкладка вернулась на страницу QR-входа. Причина без сетевых ответов не установлена; поддержку одновременных веб-сеансов и стабильность авторизации необходимо проверить отдельно.

Следующая проверка должна проходить в отдельном окне Chrome с единственной вкладкой Tuya либо по выбранным ответам Network, предоставленным владельцем. Достаточно проверить список, Device Info шлюза, Wi-Fi устройства и Zigbee child на поля ключа, родителя и `cid`; значения ключей не должны попадать в отчёт или Git.

Даже если ключ найден, для автоматического адаптера отдельно нужны проверенные авторизация, срок и обновление сеанса, права, пагинация и формат родителей/children. Веб-токен нельзя считать взаимозаменяемым с token_info Sharing SDK. Пока веб-адаптер и перенос реальных устройств в БД сервиса не реализованы.

Для локального управления после импорта по-прежнему нужны LAN IP и версия, подтверждённые в локальной сети. Zigbee child управляется через реквизиты родительского шлюза и свой `cid`. Существующий [QR-режим сервиса](qr-login.md) остаётся отдельным поддерживаемым способом авторизованного получения доступных метаданных и ключей.
